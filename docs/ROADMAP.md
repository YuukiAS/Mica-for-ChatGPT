## 2. 每一步的实际工作和不可跳过的验收门

### 05 安全：先改默认值和执行前检查

审查 `settings-model.ts`、`content.ts`、`recovery-controller.ts`、状态机/动作策略及后台 worker。自动刷新、Stop、assistant retry、确认未提交重发在首次预发布**默认不可自行执行**；旧安装设置、导入和后台重启不能复活危险选项。所有自动 `location.reload()` 必须在**执行当下**再核对当前标签/会话身份、可信已提交信号、草稿和发送后新输入、streaming/工具/文件/连接器/授权及其他外部副作用、次数限制与后台去重锁；锁定聊天、PIN 重新认证、临时/敏感会话及无法识别的权限状态不允许自动刷新。任何证据缺失则取消自动动作。不能只修状态机而绕过执行器。保留只读诊断与未来可配字段，不能关闭四核心功能造 PASS。对未提交、迟到提交、重复命令、旧配置、跨标签、存储失败建立旧坏/新好生产路径测试。安全关口未过不得要求用户安装到日常登录态。

### 06 兼容性：真实界面先于按钮与测试，且包含 GPT-6

用有界公开只读页面、当前兼容性命令 `chatgpt-ui:verify/refresh/diff`、开发 QA 导出必要的去敏结构/尺寸证据。分别验证：assistant/user 回合身份、原生 Copy 按钮及共同容器、按钮相对间距；静态 Markdown、表格、代码、引用、图片与来源；KaTeX/MathML 的 raw TeX 和区间；GPT-6 图表、按钮、表单及智能交互块；渐进生成/settled；编辑/分支、工具/授权、textarea/contenteditable、mention/Connector、虚拟滚动和暗色/窄宽变体。不同推理模式只作为观察环境，不是选择器开关。另须区分 Chat 与 Work、普通/锁定/临时聊天、Projects 及不属于 Mica 当前功能承诺的 Slides/Sites 等产品表面；未知界面不得注入或刷新，也不为识别页面收集私人正文。对每项保留真实来源、观察时间、能力/变体 ID、不变量、去敏证据哈希、失效范围。若实站没有观察到，不得用模拟 fixture 把 `UNKNOWN` 改成 `EXACT`。已验证的正常页面必须确实能通过生产 `ChatGPTAdapter`，不能仅修改 JSON，代码仍拒绝所有非测试页面。仅在公开路径无法证明实现前关键结构时触发 H0。

### 07 前端：五个可见表面必须做完

**回答按钮**：已证实的原生操作区只有一个自然的 Mica 入口；复制 Markdown 和 PDF 操作清楚、不会误绑相邻回答；图标不能是最终粗糙的单字母占位，尺寸、基线、悬停、键盘、关闭和 remount 安全。当前无法证明位置时安全不注入、保留浏览器右键**后备**，但不算回答内联按钮完成。

**选区工具条**：只在合法选区出现四色高亮、换色/删除、必要的当前回答清理；不盖住选中文本、原生菜单、composer 或智能交互控件，选区折叠/路由变化后消失。

**扩展弹窗**：总开关、页面兼容、Low Memory/完整历史恢复、明确可用的回答复用和偶发故障；未证明完整会话就不能把一个永远 Disabled 的按钮排在首页最显眼处。正常页面不出现 Atlas、测试面板、原始 selector 或审查角色。

**设置页**：常用高亮、复制/PDF、低内存优先；危险自动恢复阈值、诊断、历史和次要功能放高级区；所有用户可见设置都要真正生效且升级不丢旧偏好。

**PDF 文件和预览**：专业排版、分页、标题、表格、代码、引用、公式和标注；**不把 MathML 回退数、内部高亮统计、测试协议、生产过程故事写进正文**。复杂交互/图表若只能提供静态部分，必须明示非交互/不完整范围，不能无声丢内容。

覆盖亮/暗、弹窗 320—400px、100/125/150% 缩放、不同回答类型、真实指针/键盘/输入法、焦点、遮挡和反馈。必须由 Frontend Design 正式工作流和 Producer 整体阅读体验检查，不接受纯像素匹配作为视觉审查。

### 08 完整候选：让旧错误在正常测试中确实失败

重新冻结新的版本、构建及受影响证据，严守 `acceptance:preflight/ focused/ candidate` 单一验收入口；使用 Playwright 官方推荐的持久 Chromium 扩展环境，真实安装 Manifest V3，不因模拟 `chrome` 或直接 `addScriptTag` 成功冒充端到端。真实派生的动作区/数学/智能组件/流式样本是主发布场景；合成额外坏例用于健壮性，不等于实站。至少注入错误父容器、错回答、重复按钮、虚假 settled、过期选区、错数学 TeX、PDF 不可连续选择、低内存只隐藏 DOM、草稿非空自动刷新/误双发、假的截图/候选版本。Producer 先机械与整体视觉自检，再由实际产物独立 Reviewer 检查当前构建，最后一次 GPT Work 整体产品评审；两者不让用户代劳。报告必须附可回读机器候选、原始证据、候选/验证器/来源哈希、真正运行命令、失败范围及候选失效规则；旧 `0.5.16` 本地 20/20 不自动继承新版本。

### 09 H1：只有这时让用户做一次集中实站验收

由 Codex 先提供在 **8 GB MacBook Neo** 可以直接安装的 ZIP（不是 Windows 的 `D:\Code\...` 路径）和已自测的最小化操作。用户使用现有登录态的一条完整普通数学回答与一条超过 80 回合的已有长对话，在**同一次会话**完成：真实 Mica 内联按钮/备用右键 → 系统剪贴板 Markdown/TeX → 跨公式高亮/刷新 remount → PDF 正文/公式选择和颜色 → Low Memory 最近 40 回合/`Load full history`/恢复原生历史；有已存在的交互式回答才顺便验其声明范围，不要求用户为测试专门发新提示词。可得的轻干扰内存指标注明物理机器/条件；只有主观体验则如实报告，不冒充物理 A/B/C。由 Mica 提供一键去敏摘要；不要求用户开 DevTools、复制 DOM、贴聊天全文或多轮对照。

### 10 首次核心发布门

独立审查、05 安全、06 实站合同、07 UI、08 自动回归、09 H1 必须共同闭环；若内联按钮未证，必须明示“前端目标未完成/受限发布候选”，不能凭右键备用假称完成。按已授权受保护流程合并 `main`，**从最终合入提交**构建版本、ZIP/sha256 和中文 Release，上传后回读 tag、commit、资产与真实安装表现。未达标只保留未发布候选，严重问题可以禁用相关能力、回滚已验证包；不能宣称稳定版。

### 11 普通网页高亮与颜色语义

对照实际 [Web_Highlighter](https://github.com/YuukiAS/Web_Highlighter)，使用 Mica 现有普通网页模块实现精确站点权限、语义锚点、跨正文/段落/公式选区、刷新/网站动态重绘恢复、换色/删除、备注/标签、本地备份和权限撤销。网页 PDF 导出时必须继承有证据的高亮且保持文本可选。现有四个基础色**黄、薄荷绿、蓝、粉**不能冒充用户完整阅读配色偏好：**粉=疑惑，蓝=方法，绿=术语，红/橙/黄=优先级**；完成必要新颜色、可配置语义和旧记录迁移。不能为了颜色把用户语义强行内置成不可改的规则。最终无需并装 Web Highlighter 或 AI Exporter。

### 12 Notion 数学：不接受“粘贴了一串 LaTeX 就算成功”

沿用 `AnswerDocument`、Markdown/富剪贴板与导入文件，但以真实 Notion 中一次粘贴/导入后的**可编辑原生 equation 对象**为验收结果。覆盖大量中文行内公式、块级公式、连续公式、公式与标点以及列表/表格/代码/链接混排。不能把 `\(...\)` 替换为 `$...$` 就声称解决“不再逐个 Ctrl+Shift+E”。默认不要求先连 Notion；不支持的公式/交互内容必须标明可验证的降级路径，模拟可编辑框和 MIME 检查只作支撑。真实目标可集中在 H2。

### 13 后续高级功能，分四条子轨道，不能笼统标“后端完成”

- **13A 断流/幽灵发送/刷新重试**：区分正常长思考和**约 60 秒无结构进展**；刷新后“连接已中断、等待完整答复”、消息未提交、延迟提交、已提交未完成、旧答案重放分别绑定可信身份与安全动作。停止/刷新/重试/真正未提交的最多一次重发由设置控制、有次数和间隔、跨刷新去重及 kill switch，未知/工具副作用不自动重复发送。不要仅凭 60 秒无新文字结束合法长任务。**刷新后立即中断分支**：如果首次有限且安全的刷新后已明确出现“连接已中断，正在等待完整答复”，马上判断中断状态，不再机械等待第二次 60 秒。仅在已确认同一个 user turn 提交成功、当前没有草稿/授权/工具写入及重复动作风险且原生控件身份可靠时，才可按配置上限终止当前生成、再次安全刷新或执行同轮恢复；提交状态未知时绝不能直接重发新 user 消息，必须保留草稿并提供人工动作。文案本身不构成自动重发许可。
- **13B 输入框与连接器**：`@GitHub`/mention 选择、发送后残留、Ctrl+A/Delete/cut、contenteditable/textarea remount、剪贴板、输入法、用户发完后的新草稿、连续发送；先做 Mica ON/OFF 对照，不把宿主原生问题归因给 Mica；提交不确定绝不清草稿，普通键入热路径不做广泛 DOM 读取/克隆/布局/大文本哈希。
- **13C 已知纯确认与页面辅助**：严格白名单处理旧“请求过于频繁/明白了”提示，不绕限流；未知、安全、登录、授权、删除、支付、文件/工具确认绝不自动点击；`Hide suggested work` 必须当前实站唯一命中、关闭或 remount 后可逆恢复，不误隐藏真实建议。
- **13D 条件性 Clear Writing/其他选定工具挂载**：此前要求在 Project 中尽量稳定调用明确选定的写作工具，这是一个**有条件的 Mica 集成研究项**。先证实原生项目设置/插件选择是否稳定；若不可靠且安全、支持的可见 UI 可承接，才研究发送前自动挂载，必须确证目标插件身份/真正调用/不双发/不丢稿/不自动送出/遇未知结构可关闭。**不假设插件能改变模型内部调用，也不以插入提示词冒充已经调用 Clear Writing。** 条件不成立则报告无需/不能安全介入，不阻碍已经交付的四核心。
  
这四轨对应现有统一设置的安全参数与高级区域；未完成部分不得默认启用高风险动作，也不能另外增加常驻诊断浮窗。

## 5. 用户真实浏览器要打开多少次、什么情况下可以增加？

这里的“1 次”是**一次集中人工验收会话**，允许多个既有标签页和必要刷新，不等于只打开一次网页或点一次鼠标。Codex 日常在隔离 Playwright Chromium 运行真实扩展，不计用户介入；禁止自动接管日常登录态 Edge/Chrome、上传私有对话或触发带副作用工具。

| 关口 | 唯一合法触发 | 用户最少操作 | 预算 |
|---|---|---|---|
| **H0 可选前期只读** | 06 已完成公开只读与隔离路径审计，关键按钮位置或智能 UI 的**必要结构**仍只有登录态可获得 | 已有 ChatGPT 页面，一键导出经本地自测的去敏结构，不发提示词、不抓全文 | **0 或 1 次** |
| **H1 首次核心发布前** | 05—08 完成，候选冻结、独立 Reviewer/GPT Work 已完成 | 8GB MacBook Neo 一次验收：实际按钮/右键、Markdown/TeX 剪贴板、高亮跨数学/刷新、PDF 真实选区、40 回合与完整历史恢复 | **1 次** |
| **H2 完整首版前** | 11—13 完成自动与独立审查，真实 Notion/权限/安全行为仍需确认 | 一次综合网页、Notion、ChatGPT 已授权无危险的功能验收 | **计划 1 次**；合法独立证据可减少 |

**计划人工总数：核心首次预发布需 1 次，若 H0 不可替代则 2 次；完整产品累计需 2 次，若 H0 必需则 3 次。** 这是当前已知需求下的计划预算，不是未来未知界面的无条件保证。

**额外人工操作的唯一例外处理**：Codex 必须先独立提交“失败能力与原始去敏证据、为什么旧真实派生 fixture 与独立观察不足、是否能安全关闭该功能继续受限发布、唯一最小人工动作、会使哪个既有候选验收失效”，由现有产品决策权归口处理；不能自行把 H1 变成五轮重复发送/截图。人工首次发现故障后必须先形成旧坏/新好离线回归；修复后只有实站行为无法由可信独立证据重新证明时才可请求额外验证，不能为了压低次数虚报已验。

### 6.1 首次预发布不能退让的条件

安全默认关闭并有执行前保护；当前 GPT-6 的已承诺普通页面范围可用且未知交互被明确降级；内联 Mica 按钮自然可见、目标归属唯一（如依赖真实结构未证实，**不得偷换右键备用为 UI 已完成**）；高亮跨公式/恢复、PDF 实际可选数学及高亮、Low Memory 完整历史可恢复；弹窗/设置/PDF 产品级质量；候选 SHA/控制集和独立产品审查；H1 真实登录态及 MacBook Neo 的最低必要证据；最后实际 GitHub 预发布 ZIP、SHA、tag 和中文说明一致。缺硬条件只能标“未验/受限候选”，不能正式宣称四核心完成。

### 6.2 完整首版额外条件

普通网页高亮/按站点授权/网页 PDF、Notion 的真实数学对象、高级恢复与 composer/Connector 稳定性、已知弹窗/建议工作控制均按承诺的范围验收；13D 按原生插件实验得出“安全需要并已实现”或“不需要 Mica 介入”的独立结论，不能暗中删除历史需求；H2 与全部受影响候选的独立审查完成、Issue/PR 逐项正确关闭/保留；重新从最终主线提交打包发布。

### 6.3 失效、停止与回滚

- 若某一页面能力漂移，只使它 `UNKNOWN` 并停用其依赖功能，其他已验证能力正常运行；Developer QA 去敏采样 → compatibility diff → 真实派生旧坏新好 → focused 验证 → 新版本，不再无限建 Atlas。
- 涉及丢稿、双发、自动刷新错误或服务器历史恢复失败时，先关闭该危险功能、保存用户已有高亮/设置、恢复原生行为；回滚到**已验证具体安装包**，不采用随意 Git reset 代替用户侧回滚。
- 更改被审查代码、导出模型、合同、截图基线或验证器后，受影响候选证据失效；禁止“改产品同时偷偷更新黄金答案”，截图基准更新必须独立接受；同类失败两次无新证据先查根因/测试保真，不重复昂贵压测。
- 普通补丁默认由最小受影响自动化、真实扩展回归和必要的独立质量检查完成；没有新的登录态不可替代风险就**不再要求用户手动打开 ChatGPT**。
