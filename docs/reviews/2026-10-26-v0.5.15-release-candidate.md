## 结论

本次产品运行时复核面向提交 `108525bb0b81f5d2febb4ee3fe09e6519f300b02`、运行时版本 `0.5.15` 和构建标签 `product-delivery.2`；Low Memory 最新压力证据与验收器失效规则补强面向提交 `a8cc91518f47c4e48c05bd61d7aa6d0fd193f711`。在不访问真实 ChatGPT、不接触用户日常浏览器配置的边界内，当前候选已通过真实安装扩展、隔离 Chromium、实际扩展页面、实际三页 PDF、Low Memory 生命周期与 0.5.15 A/B/C 压力复测、视觉基准及 acceptance control corpus 的联合验证。

## 本轮发现与处置

强化真实扩展 PDF 路径时，测试发现列表高亮已经写入本地存储，却没有出现在实际 PDF 页面。根因是 `AnswerDocument` 的高亮投影在相邻 `<li>` 之间没有写入换行，而 PDF 序列化会插入换行，导致同一版本的 `sourceSpan` 与导出文本错位。

候选已在列表投影中加入与 PDF 序列化一致的换行分隔，并补充两层回归：聚焦 fixture 验证第二个列表项的文字区间能准确回读；真实安装扩展 E2E 则同时保留一个内容变化后不再唯一的旧锚点，并新建一个当前版本高亮，确认 PDF 只解析当前高亮、把旧锚点留为 unresolved。该修复形成了新的运行时版本 `0.5.15`。

## 尚未越过的边界

除真实登录态 ChatGPT 与目标物理低内存设备外，未发现还能通过本地源码、隔离浏览器、fixture、实际扩展页面、PDF 或 acceptance validator 继续补齐的核心证据。剩余工作是人工外部边界，而不是新的本地实现缺口：

1. 在扩展管理页重新加载 `dist/mica-dev`，确认显示 `0.5.15`。
2. 在真实 ChatGPT 上对一条稳定回答执行右键复制，并核对系统剪贴板。
3. 创建一条真实高亮，经历回答重新挂载后确认恢复，并导出 PDF 检查高亮。
4. 在真实长会话中确认 Low Memory 最近 40 条窗口与 `Load full history` 恢复。
5. 在目标物理低内存设备上确认体验和资源改善。

上述验收通过后，仍应从最终合入提交重新生成并校验 ZIP，再由受保护流程决定是否合入 `main` 和创建 GitHub Pre-release。
